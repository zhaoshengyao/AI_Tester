# AI 执行最小规则

本文件是 AI 进入项目时的默认轻量入口，用于减少重复读取和 token 浪费。

## 默认读取顺序
1. 先读本文件。
2. 再读与当前阶段直接相关的 1 到 2 份正式输入。
3. 只有正式输入无法回答问题、存在统计冲突、或需要追证时，才展开更多报告、原始结果或脚本。

## 默认不做的事
- 不把整目录扫描当成默认动作。
- 不默认整包读取 `docs/reports/`、`docs/defects/`、`docs/knowledge/`、`tests/`。
- 不把“阶段细化方案”当成固定上下文；只有当前 skill 未覆盖细节时才按需参考。
- 搜索或统计脚本时默认排除依赖、虚拟环境、缓存、报告和历史归档原始结果，例如 `node_modules/`、`.venv/`、`__pycache__/`、`.pytest_cache/`、`reports/`、`test-results/`、`playwright-report/`、`docs/test-runs/*/raw/`。
- 静态收集 pytest 用例时不得写入正式报告目录；使用 `python -m pytest --collect-only -q -o addopts=''`，或把 HTML/JUnit 输出指向临时目录。

## 文档职责分工
| 文档 | 默认用途 | 不应承担的用途 |
|------|----------|----------------|
| `docs/test-runs/YYYYMMDD-HHMMSS/批次摘要.md` | 当前批次的快速事实入口、关键口径、证据入口、下一步决策 | 不必展开所有细节分析 |
| `docs/reports/系统测试报告.md` | 审计汇总、全局判断、跨专项一致性、上线建议、闭环状态 | 不重复铺陈批次摘要里已有的统计明细 |
| `docs/knowledge/*.md` | 可复用规则、模式、索引、维护动作、回归资产 | 不重复记录当前批次快照 |
| `docs/reports/*阶段细化方案.md` | 编写配置或补规则时的参考资料 | 不作为阶段默认输入 |

## 冲突时的处理
- 统计冲突时，优先检查专项正式报告、覆盖矩阵、缺陷清单，再回看原始结果。
- 事实已在上游摘要稳定表达时，下游文档应引用，不应整段重写。
- 需要长期复用的信息优先沉淀到索引、矩阵、模式库和维护清单，而不是重复写进多个长文档。

## 真实接口优先
- 只要被测系统和真实接口可访问，接口分析、接口用例、API 自动化断言和系统报告结论都必须以实测接口行为为最高优先级。
- 有接口文档时，文档用于对照差异；实际接口与文档不一致必须写入“文档与实际接口差异/待确认”，不得在未确认前按文档把真实实现判为失败。
- API full 已真实执行并出现失败项时，所有失败项都必须进入接口缺陷清单；文档差异、路由差异、方法差异或字段契约差异类失败，按“接口契约/文档一致性缺陷”或“接口契约/实现一致性缺陷”登记，关闭方式由责任方处理结果决定。
- 没有接口文档时，必须通过前端 Network、页面操作、源码线索、接口探测或现有脚本形成“实测接口基线”，再基于基线设计用例和断言。
- 只有产品/研发明确确认“以接口文档为准”，或评审版用例标记为“已确认契约”时，文档契约才可作为硬断言和缺陷判定依据。

## 测试执行规则（禁止猜测）
| 规则编号 | 规则描述 | 适用场景 |
|----------|----------|----------|
| TR-001 | 必须先通过浏览器Network或API探测确认真实接口，禁止基于原型文档猜测接口路径 | 接口分析、接口测试 |
| TR-002 | 数据一致性测试必须直接使用系统返回的统计接口数据，禁止自行通过基础CRUD接口聚合计算 | 数据一致性测试 |
| TR-003 | 统计口径（时间范围、用户范围、数据定义）必须与系统保持一致，禁止假设统计逻辑 | 数据一致性测试 |
| TR-004 | 接口字段名必须通过实际返回值确认，禁止基于文档或经验推断字段名 | 所有API测试 |
| TR-005 | 发现数据不一致时，必须先对比系统接口返回值与测试计算值，分析差异原因，而非直接修改断言 | 数据一致性测试 |
