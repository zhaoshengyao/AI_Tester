## 1. 架构概览

### 1.1 设计理念

AutoTest Hub 采用 **"Windows 开发 + Linux 执行"** 的双平台协作模式，充分利用两个平台的优势：

| 平台 | 角色 | 优势 |
|------|------|------|
| **Windows** | 开发与设计 | AI 辅助编码、文档编辑、图形化界面 |
| **Linux** | 执行与验证 | 稳定环境、资源充足、接近生产环境 |

### 4.4 编写测试脚本

#### 4.4.1 API 测试脚本

**文件位置**: `tests/api/testsuites/crm/`

**编写规范**:
```python
import pytest
from tests.api.clients.crm_client import CRMClient

class TestCustomerCRUD:
    """客户 CRUD 测试"""
    
    def test_create_customer_success(self, crm_client, authorized_headers):
        """创建客户 - 成功"""
        data = {
            "customerName": "测试客户",
            "contactPhone": "13800138000"
        }
        response = crm_client.create_customer(data, headers=authorized_headers)
        assert response.status_code == 200
        # 更多断言...
    
    def test_read_customer_list(self, crm_client, authorized_headers):
        """查询客户列表"""
        response = crm_client.get_customer_list(headers=authorized_headers)
        assert response.status_code == 200
        assert "data" in response.json()
```

#### 4.4.2 UI 测试脚本

**文件位置**: `tests/ui/specs/`

**编写规范**:
```typescript
import { test, expect } from '@playwright/test';
import { LoginPage } from '../pages/LoginPage';
import { CustomerManagementPage } from '../pages/CustomerManagementPage';

test.describe('客户管理', () => {
  test('客户列表页面可达', async ({ page }) => {
    const loginPage = new LoginPage(page);
    await loginPage.goto();
    await loginPage.login('admin', 'password');
    
    const customerPage = new CustomerManagementPage(page);
    await customerPage.goto();
    await expect(customerPage.pageTitle).toBeVisible();
  });
});
```

### 9.2 依赖问题

#### Q3: pip 安装失败

```bash
# 使用国内镜像
pip3 install -i https://pypi.tuna.tsinghua.edu.cn/simple package_name

# 或者使用 --break-system-packages（新版 pip）
pip3 install --break-system-packages package_name
```

#### Q4: Node.js 版本过低

```bash
# 下载安装 v20
cd /tmp
curl -fsSL https://nodejs.org/dist/v20.11.0/node-v20.11.0-linux-x64.tar.xz -o node.tar.xz
tar -xf node.tar.xz
mv node-v20.11.0-linux-x64 /usr/local/node-v20
ln -sf /usr/local/node-v20/bin/node /usr/local/bin/node
ln -sf /usr/local/node-v20/bin/npm /usr/local/bin/npm
node --version
```

#### Q5: Playwright 浏览器下载失败

```bash
# 设置代理或使用镜像
PLAYWRIGHT_DOWNLOAD_HOST=https://npmmirror.com/mirrors/playwright npx playwright install chromium

npx playwright install chromium --dry-run
```

## 10. 最佳实践

### 10.1 代码规范

| 规范 | 说明 |
|------|------|
| **命名** | 使用有意义的变量名和函数名 |
| **注释** | 关键逻辑添加中文注释 |
| **断言** | 每个测试至少 2 个断言 |
| **清理** | 测试后清理创建的数据 |
| **隔离** | 测试之间相互独立 |

### 10.2 Git 规范

#### 分支策略

```
main (生产)
├── develop (开发)
│   ├── feature/customer-crud
│   ├── feature/business-flow
│   └── fix/login-bug
└── hotfix/critical-issue
```

#### 提交信息格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

示例：
```
feat(api): 添加客户 CRUD 接口

- 实现 create_customer 方法
- 实现 get_customer_list 方法
- 实现 update_customer 方法
- 实现 delete_customer 方法

Closes #123
```

### 10.3 测试规范

#### 分层执行

```
L1: 单元测试 (开发机)
    └── python -m pytest tests/unit/ -v

L2: API 测试 (开发机/服务器)
    └── ./scripts/run-api-tests.sh full

L3: UI 测试 (服务器)
    └── ./scripts/run-ui-tests.sh

L4: 性能测试 (服务器)
    └── ./scripts/run-perf-tests.sh stress
```

#### 覆盖率要求

| 测试类型 | 目标覆盖率 | 执行频率 |
|----------|-----------|----------|
| API 冒烟 | 核心接口 100% | 每次提交 |
| API 全量 | 所有接口 95%+ | 每日 |
| UI 冒烟 | 核心页面 100% | 每次提交 |
| UI 全量 | 所有页面 90%+ | 每日 |
| 性能冒烟 | - | 每次提交 |
| 性能常规 | - | 每日 |

### 10.4 安全规范

| 规范 | 说明 |
|------|------|
| **密码** | 不硬编码在脚本中，使用环境变量 |
| **Token** | 不提交到 Git，使用 .gitignore |
| **密钥** | 使用 SSH 密钥认证，不使用密码 |
| **权限** | 最小权限原则 |
