# 测试知识沉淀目录

本目录用于保存完整测试流程结束后的可复用知识资产。

## AI 默认读取顺序
为减少 token 浪费，AI 默认按以下顺序读取：

1. `docs/knowledge/README.md`
2. 与当前任务直接相关的 1 到 2 个知识文件
3. 只有在索引无法回答问题时，再展开更多知识文件

不要把 `docs/knowledge/*.md` 全部作为默认输入。

## 建议文件与用途

## 何时读取哪份文件
| 文件 | 默认是否读取 | 适用场景 |
|------|--------------|----------|
| `测试知识库.md` | 是 | 想快速了解当前项目已验证的业务规则、接口契约和流程经验，特别是密码加密规则、认证机制、测试环境配置 |
| `需求变更影响索引.md` | 否 | 做变更影响分析、回归范围评估时读取 |
| `回归测试资产索引.md` | 否 | 选择回归子集、确定优先级时读取 |
| `缺陷模式库.md` | 否 | 做缺陷复盘、评审或新项目风险预检时读取 |
| `自动化资产维护清单.md` | 否 | 维护脚本、评估自动化稳定性时读取 |
| `环境与工具问题库.md` | 否 | 工具不可用、归档异常、编码问题时读取 |
| `嵌入式端云联调知识库.md` | 否 | 只有 protocol-cloud 相关任务时读取 |
| `下一轮迭代测试建议.md` | 否 | 规划下一轮回归或新版本测试节奏时读取 |

## 使用原则
- 历史知识是“参考输入”，不是每个阶段都必须整包回读的固定上下文。
- 已经能从本轮批次摘要、系统测试报告或覆盖矩阵回答的问题，不必再回头读取知识库正文。
- 知识文件以“可复用规则、模式、索引、维护动作”为主，不重复记录当前批次的执行快照。
- 当前批次事实优先保留在 `docs/test-runs/YYYYMMDD-HHMMSS/批次摘要.md` 和 `docs/reports/系统测试报告.md`。

知识沉淀必须基于已读取文档、已评审用例、已执行结果、缺陷清单和系统测试报告；证据不足时写“待确认”。
