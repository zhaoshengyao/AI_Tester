# 输入
- `docs/AI执行最小规则.md`
- `docs/analysis/需求分析报告.md`
- `docs/test-plan/测试方案.md`
- `docs/test-plan/测试计划.md`
- `docs/reports/测试用例生成阶段细化方案.md`（仅在当前 SKILL 未覆盖细节时按需读取）
- `docs/protocol/`
- `docs/device/`
- `docs/阶段执行检查清单.md`

# 输出
- `docs/cases/嵌入式测试用例.md`

# 工作流
1. 读取需求分析报告、测试方案和测试计划。
2. 确认嵌入式第一版范围仅为协议/端云联调。
3. 提取协议入口、设备身份、上报样例、平台接收、API 查询、UI 展示和协议/端云待确认项。
4. 生成本轮正式协议/端云联调用例。
5. 将固件、硬件、OTA、HIL、串口日志、断电/弱网等写入后续范围或 blocked，不混入正式执行用例。
6. 为每条用例标记优先级、自动化结论、执行层级、来源依据和追踪标识。
7. 输出生成统计和风险与待确认项。

# 覆盖维度
- 协议字段合法性
- 字段类型、单位、枚举
- 设备身份和绑定关系
- 正常上报
- 异常上报
- 重复上报和幂等
- 平台接收和状态更新
- API 查询一致性
- UI 展示一致性

# 用例字段
- 序号
- 用例编号
- 模块/场景
- 用例标题
- 前置条件
- 测试数据
- 操作步骤
- 预期结果
- 优先级
- 自动化结论
- 执行层级
- 来源依据
- 追踪标识

# 编号规则
- 用例编号使用 `EMB-模块-序号`，例如 `EMB-PROTOCOL-001`。
- 序号列用于表格计数，必须位于用例编号前，从 1 连续递增。

# 自动化与层级
| 场景 | 自动化结论 | 执行层级 |
|------|------------|----------|
| 设备上报后平台可查询 | 自动化 | smoke |
| 协议字段、API 查询、UI 展示链路 | 自动化 | protocol-cloud |
| 异常报文、重复上报、非法枚举 | 自动化或阻塞 | protocol-cloud |
| 缺协议文档、设备身份或上报入口 | 阻塞 | blocked |
| 固件、硬件、OTA、HIL、串口日志 | 阻塞或后续范围 | blocked |

# 强制规则
- 必须同时对齐 `docs/analysis/需求分析报告.md`、测试方案和测试计划。
- 每条正式用例必须能追溯到需求分析报告中的协议/端云联调初步分析、设备身份、上报入口、API 查询或 UI 展示。
- 如果测试方案与需求分析报告不一致，不得自行选择口径；必须记录差异并标记待确认。
- 需求分析报告没有依据、但测试方案认为需要覆盖的内容，必须标记“来源待确认”。
- 不得生成固件烧录、串口日志、OTA、HIL、硬件接口、断电/弱网/异常注入的本轮正式执行用例。
- 不确定的前置条件、测试数据、预期结果必须写“待确认”。
- 不得只写“正常”或“成功”作为预期结果。
- 必须输出生成统计：正式用例数、后续范围/阻塞数、优先级分布、自动化结论分布、执行层级分布。
- 只输出嵌入式协议/端云联调用例，不输出功能、接口、性能或安全用例。
- 输出必须按顺序包含：当前阶段、输入文件、产出文件、正文/核心内容、执行结论、风险与待确认项、下一步建议。正文/核心内容必须位于执行结论、风险与待确认项、下一步建议之前；执行结论、风险与待确认项、下一步建议必须作为文档收尾部分。
