# 输入
- `docs/AI执行最小规则.md`
- `docs/analysis/需求分析报告.md`
- docs/test-plan/测试方案.md
- docs/test-plan/测试计划.md
- `docs/reports/测试用例生成阶段细化方案.md`（仅在当前 SKILL 未覆盖细节时按需读取）
- docs/阶段执行检查清单.md

# 输出
- docs/cases/性能测试用例.md

# 覆盖维度
- 需求分析报告中的核心链路、核心接口、数据量风险、端云上报风险、测试关注重点
- 核心场景
- 并发模型
- TPS/QPS
- 响应时间
- 稳定性
- 容量上限
- 长稳场景
- 资源瓶颈观察点

# 用例字段
- 序号
- 用例编号
- 场景
- 并发/负载模型
- 持续时间
- 事务指标
- 资源指标
- 通过标准
- 优先级
- 自动化结论
- 执行层级
- 来源依据
- 追踪标识

# 工具路径
- JMeter 本地路径：`D:\jmeter\jmeter\bin`
- 用例生成阶段只设计性能用例，不验证或执行 JMeter。

# 强制规则
- 需求分析报告、测试方案或测试计划不存在时，不得生成正式用例
- 每条正式用例必须能追溯到需求分析报告中的核心链路、核心接口、数据量风险、端云上报风险或测试关注重点
- 如果测试方案与需求分析报告不一致，不得自行选择口径；必须记录差异并标记待确认
- 性能目标、压测环境或压测授权不明确时，必须写“待确认”
- 必须包含“序号”列，且位于用例编号或场景编号前，从 1 连续递增
- 必须包含自动化结论和执行层级，性能用例执行层级为 performance
- 必须输出生成统计：正式用例数、后续范围/阻塞数、优先级分布、自动化结论分布、执行层级分布
- 不得只写“正常”或“成功”作为通过标准
- 只输出性能测试用例，不输出功能、接口、嵌入式或安全用例
- 输出必须按顺序包含：当前阶段、输入文件、产出文件、正文/核心内容、执行结论、风险与待确认项、下一步建议。正文/核心内容必须位于执行结论、风险与待确认项、下一步建议之前；执行结论、风险与待确认项、下一步建议必须作为文档收尾部分
