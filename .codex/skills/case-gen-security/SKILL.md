# 输入
- `docs/AI执行最小规则.md`
- `docs/analysis/需求分析报告.md`
- docs/test-plan/测试方案.md
- docs/test-plan/测试计划.md
- docs/api/
- `docs/reports/测试用例生成阶段细化方案.md`（仅在当前 SKILL 未覆盖细节时按需读取）
- docs/阶段执行检查清单.md

# 输出
- docs/cases/安全测试用例.md

# 覆盖维度
- 需求分析报告中的认证、权限、输入点、敏感信息、接口暴露、异常表现
- 登录认证
- 权限绕过
- SQL 注入
- XSS
- CSRF
- SSRF
- 文件上传
- 敏感信息泄露
- Header/Cookie/Session
- 默认配置与弱口令风险

# 用例字段
- 序号
- 用例编号
- 风险类型
- 目标范围
- 前置条件
- 测试步骤
- 预期结果
- 严重级别
- 自动化结论
- 执行层级
- 来源依据
- 追踪标识

# 工具路径
- ZAP 本地安装目录：`C:\Program Files\ZAP\Zed Attack Proxy`
- 用例生成阶段只设计安全用例，不执行 ZAP。

# 强制规则
- 需求分析报告、测试方案或测试计划不存在时，不得生成正式用例
- 每条正式用例必须能追溯到需求分析报告中的认证、权限、输入点、敏感信息、接口暴露或异常表现
- 如果测试方案与需求分析报告不一致，不得自行选择口径；必须记录差异并标记待确认
- 未确认授权扫描范围时，不得生成主动攻击类执行结论
- 必须包含“序号”列，且位于“用例编号”前，从 1 连续递增
- 必须包含自动化结论和执行层级，安全用例执行层级为 security 或 blocked
- 必须输出生成统计：正式用例数、后续范围/阻塞数、严重级别分布、自动化结论分布、执行层级分布
- 不得只写“正常”或“成功”作为预期结果
- 只输出安全测试用例，不输出功能、接口、嵌入式或性能用例
- 输出必须按顺序包含：当前阶段、输入文件、产出文件、正文/核心内容、执行结论、风险与待确认项、下一步建议。正文/核心内容必须位于执行结论、风险与待确认项、下一步建议之前；执行结论、风险与待确认项、下一步建议必须作为文档收尾部分
