- `docs/AI执行最小规则.md`

- docs/test-plan/测试计划.md
- docs/api/
- `docs/reports/测试用例生成阶段细化方案.md`（仅在当前 SKILL 未覆盖细节时按需读取）
- docs/阶段执行检查清单.md

# 输出
- docs/cases/接口测试用例.md

# 覆盖维度
- 需求分析报告中的接口初步分析、实际请求响应、接口待确认项、数据交互
- 实测接口基线中的真实请求方法、路径、鉴权方式、响应字段、状态码、分页/筛选/错误响应
- 文档与实际实现差异，仅作为差异核对和待确认用例来源，不直接覆盖实测行为
- 参数合法性
- 必填校验
- 边界值
- 鉴权
- 幂等性
- 业务码
- 异常处理
- 数据一致性
- 并发与限流关注点

# 用例字段
- 序号
- 用例编号
- 接口名称
- 请求方法
- 请求路径
- 前置条件
- 请求参数
- 步骤
- 预期结果
- 优先级
- 自动化结论
- 执行层级
- 来源依据
- 追踪标识

# 自动化与层级
| 场景 | 层级 |
|------|------|
| 登录、核心只读接口、核心状态查询 | smoke |
| 列表、详情、筛选、导出响应、配置读取 | readonly-regression |
| 缺参数、非法参数、不存在 ID、未授权 | security |
| 新增、编辑、删除、处理、同步、改密 | write-regression，需回滚策略 |
| 契约不明确或数据不可控 | blocked |

# 强制规则
- 需求分析报告、测试方案或测试计划不存在时，不得生成正式用例
- 每条正式用例必须能追溯到需求分析报告中的接口路径、请求/响应、字段、数据交互或接口待确认项
- 只要需求分析报告中存在真实接口观察或实测接口基线，接口用例预期必须优先依据真实接口行为编写。
- 有接口文档但与真实接口不一致时，必须生成“文档与实际差异核对”类用例或待确认项，不得把文档字段直接写成硬预期。
- 没有接口文档时，不得写“按接口文档应返回”；必须基于实测接口基线写可达性、响应结构、业务一致性、鉴权和错误处理预期。
- 只有当需求分析报告明确写明“产品/研发确认以接口文档为准”时，才允许把文档契约写入强断言预期。
- 如果测试方案与需求分析报告不一致，不得自行选择口径；必须记录差异并标记待确认
- 需求分析报告没有依据、但测试方案认为需要覆盖的内容，必须标记“来源待确认”
- 接口文档缺失时，已通过实测接口基线确认的字段、鉴权和业务码可作为实测预期；无法从实测确认的内容必须标记为“待确认”
- 必须包含“序号”列，且位于“用例编号”前，从 1 连续递增
- 必须包含自动化结论和执行层级
- 必须输出生成统计：正式用例数、后续范围/阻塞数、优先级分布、自动化结论分布、执行层级分布
- 不得只写“正常”或“成功”作为预期结果
- 只输出接口测试用例，不输出功能、嵌入式、性能或安全用例
- 输出必须按顺序包含：当前阶段、输入文件、产出文件、正文/核心内容、执行结论、风险与待确认项、下一步建议。正文/核心内容必须位于执行结论、风险与待确认项、下一步建议之前；执行结论、风险与待确认项、下一步建议必须作为文档收尾部分
