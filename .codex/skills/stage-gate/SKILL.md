# 输入
- `docs/AI执行最小规则.md`
- `AGENTS.md`
- `stage-manifests/*.yaml`
- `docs/阶段执行检查清单.md`
- `docs/reports/参考资料索引.md`
- `docs/reports/完整测试流程重构方案.md`（仅在当前 SKILL 未覆盖细节或需追溯历史设计时按需读取）
- `docs/reports/自动化与专项执行阶段编排方案.md`（仅在当前 SKILL 未覆盖细节或需追溯历史设计时按需读取）
- 当前阶段所需输入文件
- 当前阶段上一阶段产出文件
- 被测地址、账号、设备/协议、工具配置等环境信息

# 输出
- 阶段门禁结论
- 必需输入检查结果
- 必需产出检查结果
- 环境与工具检查结果
- 阻塞项、待确认项、未执行范围
- 测试时间归档检查结果：每轮执行类阶段必须存在 `docs/test-runs/YYYYMMDD-HHMMSS/` 或明确未归档原因

# 工作流
1. 确认当前阶段名称和目标，不推断用户未明确要求的阶段。
2. 先读取 `docs/AI执行最小规则.md`，再读取 `docs/阶段执行检查清单.md` 和当前阶段所需输入。
2.1 机器可读门禁与完成判定优先读取 `stage-manifests/*.yaml`；需要代码侧结论时调用 `scripts/check-stage.ps1` / `scripts/check-stage.sh`，不要再手工复制一套条件。
3. 检查上一阶段产出是否存在、非空、且结论有来源。
4. 检查当前阶段必需输入是否存在；缺失时标记“待确认”或“未执行”。
5. 自动化或专项执行前，先检查覆盖矩阵是否存在。
6. 执行类阶段前，检查被测服务/API 基础门禁。
7. API 执行前，检查接口断言来源是否已分层：实测接口基线、文档差异核对、已确认契约断言。
8. API/UI 执行前，判断是否满足受控并行条件。
9. 性能测试前检查 API/UI 自动化是否完成或明确未执行原因，并检查 JMeter、压测参数、授权。
10. 安全测试前检查性能测试是否完成或明确未执行原因，并检查 ZAP、扫描范围、认证方式。
11. 嵌入式第一版只检查协议/端云联调门禁：协议文档、设备身份、上报方式、上报样例、平台账号、API 查询能力、数据清理。
12. 进入系统测试报告前，检查各专项报告、覆盖矩阵和缺陷清单；缺失的专项必须能追溯到“未执行”原因。
13. 进入测试知识沉淀前，检查系统测试报告是否存在，并确认知识沉淀不会修改历史报告和执行结果。
14. 检查本轮产出是否按测试时间归档到 `docs/test-runs/YYYYMMDD-HHMMSS/`。
15. 输出允许进入、禁止进入、部分允许进入三类结论。
16. 执行类阶段完成冒烟后，检查是否已有“下一步决策”；缺失时不得默认进入下一层级。

# AI 读取优化
- 默认输入顺序：`docs/AI执行最小规则.md` -> `docs/阶段执行检查清单.md` -> 当前阶段直接输入 -> 必要环境信息。
- `完整测试流程重构方案.md`、`自动化与专项执行阶段编排方案.md` 只作为参考资料，不作为默认输入。
- 阶段门禁判断优先依据正式门禁清单和当前阶段产物，不通过长篇设计说明重复确认。

# 门禁结论
| 结论 | 含义 | 后续动作 |
|------|------|----------|
| 允许进入 | 必需输入、上一阶段产出和环境门禁均满足 | 可进入当前阶段 |
| 部分允许进入 | 仅部分执行层级满足，例如 smoke/partial | 只执行满足条件的范围 |
| 禁止进入 | 必需输入缺失、上一阶段未完成或关键环境不可用 | 写“未执行”并停止 |

# 冒烟后决策结论
| 决策 | 允许条件 | 后续动作 |
|------|----------|----------|
| continue | 冒烟通过且风险可接受 | 允许进入下一执行层级或下一专项 |
| retest | 结果疑似偶发、证据不足或与历史不一致 | 原条件或缩小范围复测 |
| collect-evidence | 发现问题但缺少定位证据 | 暂停加深执行，补日志、监控、数据或配置 |
| downgrade | 全量条件不足但子集可安全执行 | 只执行 smoke/partial/readonly/semi-auto |
| stop | 服务不可达、连接级失败、授权不足或风险不可接受 | 停止当前或后续专项 |
| handoff | 需要研发、环境或产品确认 | 只输出证据、影响和复测条件 |

# 执行顺序门禁
| 阶段 | 允许条件 | 阻断条件 |
|------|----------|----------|
| API 自动化 | 评审版接口用例、API 覆盖矩阵、服务基础门禁满足 | 服务不可达、真实认证不可用、覆盖矩阵缺失 |
| UI 自动化 | 评审版功能用例、UI 覆盖矩阵、服务基础门禁满足 | API 连接级失败、真实认证不可用、覆盖矩阵缺失 |
| 嵌入式 protocol-cloud | 嵌入式评审版用例、嵌入式覆盖矩阵、协议/设备/API 查询门禁满足 | API 连接级失败、协议/设备信息缺失 |
| 性能测试 | API/UI 已完成或明确未执行原因，且无连接级失败未处理；JMeter 与压测参数满足 | API/UI 尚未完成、连接级失败、JMeter/授权/参数缺失 |
| 安全测试 | 性能测试已完成或明确未执行原因；ZAP 与扫描范围满足 | 性能尚未完成、服务不稳定、ZAP/授权/范围缺失 |
| 系统测试报告 | 各专项报告、覆盖矩阵、缺陷清单存在，或缺失项有明确未执行原因 | 缺失项既无报告也无未执行记录，无法形成结论 |
| 测试知识沉淀 | 系统测试报告已生成，覆盖矩阵、专项报告、缺陷清单和评审版用例可读取 | 系统测试报告缺失、证据来源缺失且无法标记待确认、包含未脱敏敏感信息 |

# API/UI 受控并行
- API 与 UI 可以并行执行 smoke、readonly-regression、semi-auto。
- API smoke 出现真实登录/认证不可用时，应停止 UI 后续执行；未确认文档差异或断言口径问题不得直接停止 UI。
- 服务预检或 API smoke 出现连接级失败时，必须停止 UI、嵌入式端云联调、性能、安全；API smoke 已通过后的 API 全量局部接口失败或超时，允许 UI 按独立门禁执行，但停止嵌入式、性能、安全。
- API/UI write-regression 不默认并行；必须有数据隔离和回滚策略。
- 共用账号会被改密、禁用、删除或角色变更时，禁止并行。

# 强制规则
- 阶段门禁只判断是否能进入下一步，不生成测试用例，不执行自动化。
- 上一步输出未落盘，不得允许进入下一阶段。
- 被测服务连接失败时，API、UI、端云联调、性能、安全均不得继续执行。
- 服务预检或 API smoke 中出现服务级连接失败时，必须停止 UI、端云联调、性能、安全；API smoke 已通过后的 API 全量局部接口失败或超时，不直接停止 UI，但必须停止端云联调、性能、安全并落盘原因。
- 性能测试必须在 API/UI 自动化之后；不得早于 API/UI 执行。
- 安全测试必须在性能测试之后；不得早于性能执行。
- 覆盖矩阵缺失时，不得允许执行 API/UI/嵌入式自动化。
- JMeter/ZAP 未配置时，对应专项只能写“未执行”。
- 嵌入式第一版不检查烧录、串口、OTA、HIL、硬件接口作为必需门禁；这些能力应标记为后续范围或未执行。
- 系统测试报告不得补造专项结果；缺失报告必须写“未执行/待确认”和原因。
- 测试知识沉淀不得重新执行测试，不得修改历史报告，不得把待确认项写成确定知识。
- 测试知识沉淀必须脱敏密码、token、cookie、session、设备密钥和真实业务敏感数据。
- 每轮执行报告、覆盖矩阵、缺陷清单、原始自动化报告必须按测试时间归档到 `docs/test-runs/YYYYMMDD-HHMMSS/`。
- 冒烟完成后必须有下一步决策；没有决策时，不得默认继续全量执行、加压或主动扫描。
- 不确定的信息必须写“待确认”，不得猜测。
- 真实接口可访问时，API 门禁必须以实测接口基线为优先依据；接口文档差异未确认前不得作为 smoke 阻断。
- 没有接口文档时，不得因文档缺失阻止 API 基线测试；应要求先建立实测接口基线。
- 有接口文档但与真实接口不一致时，门禁结论应区分“接口真实失败”和“文档差异待确认/断言口径问题”。
- API smoke 失败时必须先分类：连接级失败/真实认证不可用会阻断 UI、嵌入式、性能、安全；文档差异、断言口径或非阻断业务失败只阻断 API 全量和后置专项，不阻断 UI 基础自动化。
- 输出必须按顺序包含：当前阶段、输入文件、产出文件、正文/核心内容、执行结论、风险与待确认项、下一步建议。正文/核心内容必须位于执行结论、风险与待确认项、下一步建议之前；执行结论、风险与待确认项、下一步建议必须作为文档收尾部分。
