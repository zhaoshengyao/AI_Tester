- `docs/AI执行最小规则.md`

- `docs/reports/嵌入式覆盖矩阵.md`
- `docs/阶段执行检查清单.md`

- `docs/reports/自动化与专项执行阶段编排方案.md`（仅在当前 SKILL 未覆盖细节或需追溯历史设计时按需读取）

# 输出
- `tests/embedded/`
- `tests/embedded/reports/`
- `docs/reports/嵌入式覆盖矩阵.md`
- `docs/reports/嵌入式协议端云联调测试报告.md`
- `docs/defects/嵌入式缺陷清单.md`

# 工作流
1. 先读取 `docs/AI执行最小规则.md`，再读取嵌入式评审版用例和嵌入式覆盖矩阵。
2. 确认第一版范围仅为 protocol-cloud。
3. 检查协议文档、设备身份、上报方式、上报样例、平台账号、API 查询能力和数据清理策略。
4. 设计协议客户端、测试数据、testsuites 和报告目录。
5. 生成或补齐 tests/embedded 脚本。
6. 静态校验覆盖矩阵，确认所有可自动化 protocol-cloud 用例都有脚本或阻塞说明。
7. 检查服务/API 基础门禁；API 连接级失败时停止执行。
8. 先执行协议/端云联调 smoke，验证最小上报、平台接收、API 查询链路。
9. 分析 protocol-cloud smoke 结果，区分协议样例缺失、设备身份问题、平台接收失败、API 查询失败、UI 展示不一致和环境阻塞。
10. 输出下一步决策：continue/retest/collect-evidence/downgrade/stop/handoff。
11. 仅执行下一步决策允许的 protocol-cloud 用例或复测范围。
12. 汇总协议报文、API 查询、UI/平台展示证据和失败信息。
13. 输出嵌入式协议端云联调测试报告和缺陷清单。

# AI 读取优化
- 默认输入顺序：`docs/AI执行最小规则.md` -> 评审版用例 -> 覆盖矩阵 -> 阶段门禁清单 -> 协议/设备资料。
- `自动化与专项执行阶段编排方案.md` 只作为参考资料，不作为默认输入。
- `docs/reports/嵌入式协议端云联调测试报告.md` 为正式产物名；不得写成完整嵌入式端侧测试报告。

# 执行范围
| 范围 | 第一版是否执行 |
|------|----------------|
| 协议字段一致性 | 是 |
| 设备身份和绑定关系 | 是 |
| 正常上报到平台可查 | 是 |
| API 查询一致性 | 是 |
| UI/平台展示一致性 | 是 |
| 异常报文、重复上报、非法枚举 | 条件执行，需授权和样例 |
| 固件烧录 | 否 |
| 串口日志 | 否 |
| OTA | 否 |
| HIL | 否 |
| 硬件接口 | 否 |
| 断电/弱网/异常注入 | 否 |

# 执行入口
- Windows: `pwsh -File scripts/run-embedded-tests.ps1`
- Bash: `bash scripts/run-embedded-tests.sh`

# 报告必须包含
- 执行命令、协议文档或样例来源、执行时间。
- 设备身份、产品、绑定关系。
- 上报方式、topic/path、鉴权方式。
- 协议报文、API 查询、UI/平台展示证据。
- 用例总数、执行数、通过数、失败数、未实现数、阻塞数。
- 覆盖矩阵更新结果。
- 缺陷归属：协议、后端、UI、环境、待确认。
- 明确说明未执行固件、硬件、OTA、HIL、串口日志。
- protocol-cloud smoke 后分析和下一步决策，说明为什么继续、复测、补资料、降级、停止或移交。

# 强制规则
- 评审版嵌入式用例不存在或评审未通过/有条件通过时，不得执行。
- 执行前必须先生成或更新 `docs/reports/嵌入式覆盖矩阵.md`。
- 覆盖矩阵必须逐条映射评审版嵌入式用例到脚本、执行层级、当前状态和执行状态。
- 只执行 protocol-cloud 范围；不得把固件、硬件、OTA、HIL、串口日志写成已执行。
- API 连接级失败时，嵌入式端云联调必须标记“未执行/阻塞”。
- 缺协议文档、设备身份、上报入口、平台账号或 API 查询能力时，只能写“未执行/待确认/阻塞”。
- protocol-cloud smoke 后不得默认继续全量端云联调；必须基于链路证据输出下一步决策。
- 异常报文和攻击性/破坏性输入必须有授权；未授权不得执行。
- 未实际执行时，报告必须写“未执行”并说明原因。
- 原始协议报文、API 响应和平台查询证据必须保存到 `tests/embedded/reports/` 或说明未生成原因。
- 报告必须基于真实执行结果，不得虚构通过率。
- 输出必须按顺序包含：当前阶段、输入文件、产出文件、正文/核心内容、执行结论、风险与待确认项、下一步建议。正文/核心内容必须位于执行结论、风险与待确认项、下一步建议之前；执行结论、风险与待确认项、下一步建议必须作为文档收尾部分。
