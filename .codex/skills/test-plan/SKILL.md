# 工作流
1. 读取需求分析报告
2. 提取需求分析中的模块、页面、接口、协议/端云链路、业务实体、状态流转、测试关注重点和待确认项
3. 确定测试目标、测试范围和不测范围
4. 按功能、接口、嵌入式协议/端云联调、性能、安全拆分专项策略
5. 为每个专项说明测什么、怎么测、使用什么测试方法
6. 制定自动化分层策略、覆盖矩阵策略和阶段门禁
7. 明确环境、账号、数据、设备/协议、JMeter/ZAP 等依赖
8. 输出测试方案
9. 输出测试计划

# 测试方案至少包含
- 测试目标
- 测试范围
- 不测范围
- 测试类型与覆盖策略
- 专项测试策略：功能、接口、嵌入式协议/端云联调、性能、安全
- 每个专项必须说明：测什么、怎么测、使用什么测试方法
- 自动化分层策略：smoke、readonly-regression、semi-auto、write-regression、protocol-cloud、performance、security、manual、blocked
- 覆盖矩阵策略：API 覆盖矩阵、UI 覆盖矩阵、嵌入式覆盖矩阵
- 阶段门禁：用例评审、覆盖矩阵、服务/API 基础、嵌入式协议/端云联调、写操作回滚、JMeter、ZAP
- 风险分析
- 环境与数据准备
- 交付物

# 测试计划至少包含

- 执行批次：smoke、partial、readonly-regression、protocol-cloud、performance、security、flow-closed-with-exceptions/full-flow
- 角色职责
- 环境安排
- 数据安排

- 串行阶段、可并发阶段、必须等待的门禁
- 准入条件、准出条件
- 暂停/停止条件
- 覆盖矩阵生成与评审门禁
- 风险与应对

# 专项测试策略

| 专项 | 测什么 | 怎么测 | 测试方法 |
|------|--------|--------|----------|
| 功能测试 | 主流程、页面展示、查询筛选、详情弹窗、写操作入口、权限会话、异常表现 | 按用户路径、页面状态、输入组合和权限差异设计 | 场景法、流程覆盖、等价类、边界值、组合测试、状态迁移、权限矩阵、错误推测 |
| 接口测试 | 认证、查询、详情、写接口、异常接口、实测接口基线、文档与实际差异、数据一致性 | 使用 pytest/API 请求设计参数化、正负向、实测行为断言、文档差异核对和已确认契约校验 | 正向/负向、鉴权测试、参数组合、实测基线测试、差异核对、已确认契约测试、Schema 检查、数据一致性校验 |
| 嵌入式协议/端云联调 | 协议字段、设备身份、上报链路、API 查询、UI 展示、异常报文 | 根据协议文档、设备身份、上报样例和平台查询能力设计端到端链路 | 协议一致性、等价类、端到端链路测试、端云一致性、契约测试、负向测试、幂等性 |
| 性能测试 | 核心接口、端云上报、稳定性、容量瓶颈、失败恢复 | 使用 JMeter 建立 HTTP/协议场景，按并发、时长、Ramp-up 和停止条件设计 | 基准测试、负载测试、吞吐测试、稳定性测试、阶梯压测、容量测试、恢复性验证 |
| 安全测试 | 认证、权限、输入安全、敏感信息、Header/Cookie、ZAP 扫描 | 设计 API/UI 负向访问、授权范围内攻击输入和 ZAP 扫描策略 | 鉴权测试、越权测试、注入测试、信息泄露检查、配置检查、DAST |

# 工具与门禁
- JMeter 本地路径已知：`D:\jmeter\jmeter\bin`；实际执行前仍需验证可执行文件、压测授权、并发数、持续时间、Ramp-up、停止条件、测试数据和监控指标。
- ZAP 本地安装目录已知：`C:\Program Files\ZAP\Zed Attack Proxy`；实际执行前仍需确认启动脚本或可执行文件、认证上下文、扫描范围和授权。
- 嵌入式第一版只做 protocol-cloud，即协议一致性、设备上报、平台接收、API 查询、UI 展示；不得把固件烧录、串口日志、OTA、HIL、硬件接口、断电/弱网/异常注入纳入当前必测范围。
- 写操作没有测试数据和回滚策略时，只能设计 semi-auto 或 blocked，不得计划真实执行。

# 待确认项处理
- 需求待确认影响业务规则、状态流转、权限时，进入风险与待确认项；必要时限制测试范围。
- 接口待确认影响接口用例、自动化脚本、断言时，进入接口测试风险和覆盖矩阵风险。
- 只要真实接口可访问，接口测试策略必须优先基于实测接口基线；接口文档只作为差异核对来源。
- 有接口文档但与真实接口不一致时，测试方案必须说明差异核对方式，不得把未确认文档契约计划为 smoke 硬断言。
- 没有接口文档时，测试方案必须计划通过 Network、页面操作、源码线索、接口探测或现有脚本建立实测接口基线。
- 协议/端云待确认影响嵌入式第一版时，进入协议/端云联调门禁。
- 环境/工具待确认进入阶段门禁和测试计划准入条件。
- 待确认项不阻止生成测试方案和测试计划；但影响后续执行时，必须写成准入条件、阻塞项或执行限制。

# 强制规则
- 需求分析报告不存在或仅为空模板时，不得生成最终测试方案，只能标记“待确认”
- 测试范围、不测范围、环境、数据、风险必须可追溯到需求分析报告
- 不得重复做需求分析，不得把测试方案写成需求复述
- 不得在测试方案阶段生成详细测试用例
- 不得在测试方案阶段执行测试
- 不得把未配置或未通过门禁的性能/安全写成可执行
- 不得把第一版嵌入式协议/端云联调写成完整嵌入式端侧测试
- 必须输出不测范围、不测原因、风险影响和后续触发条件
- 输出必须按顺序包含：当前阶段、输入文件、产出文件、正文/核心内容、执行结论、风险与待确认项、下一步建议。正文/核心内容必须位于执行结论、风险与待确认项、下一步建议之前；执行结论、风险与待确认项、下一步建议必须作为文档收尾部分
