# 工作流
1. 确认 `docs/reports/系统测试报告.md` 已生成；缺失时不得进入本阶段。
2. 优先读取系统测试报告和本轮 `批次摘要.md`，再按需读取覆盖矩阵、缺陷清单和专项报告。
2.1 读取本轮 `stage-status`，把统一阶段状态、未执行原因和下一步决策一起沉淀为可复用规则，不再只凭文件存在性判断。
3. 提取可复用业务规则、已验证接口行为、已确认接口契约、页面行为、协议约束和测试注意事项，生成测试知识库。
4. 建立需求/规则到页面、接口、协议、数据、用例、脚本和历史缺陷的影响索引。
5. 从评审版用例和执行结果中筛选 P0/P1 回归资产，生成回归测试资产索引。
6. 从缺陷清单和失败报告中归纳缺陷模式，说明触发条件、检测方法和预防建议。
7. 从覆盖矩阵和系统报告中提取自动化资产维护清单；只有需要确认脚本边界时，才打开具体脚本。
8. 从 run logs、未执行原因和专项报告中沉淀环境与工具问题库。
9. 第一版嵌入式只沉淀 protocol-cloud 知识，包括协议字段、设备身份、上报样例、平台接收、API/UI 展示链路。
10. 从系统测试报告中优先提取“为什么这样测、冒烟后如何判断下一步、哪些证据驱动继续/停止”的流程知识；专项报告只用于补细节，不重复抄写。
11. 抽取可跨项目、跨环境、跨模型复用的阶段门禁、冒烟脚本约束、证据采集要求和决策模式。
12. 当前批次快照、执行统计和一次性现象优先保留在 `批次摘要.md` 与系统测试报告中；知识库只沉淀可复用规则、模式、索引和维护动作。
13. 输出下一轮迭代测试建议，明确需求分析、测试设计、用例评审、自动化维护和环境准备的复用入口。

# AI 读取优化
- 默认输入顺序：系统测试报告 -> 批次摘要 -> 覆盖矩阵 -> 缺陷清单 -> 必要的专项报告 -> 必要的脚本。
- 不默认整包读取 `tests/`、历史批次归档或所有专项报告。
- 已经在系统测试报告中稳定表达的执行事实，不在知识库中整段重复抄写；知识沉淀更关注“可复用规则、模式、索引、维护动作”。
- 只有需要确认脚本路径、资产状态或具体定位证据时，才读取对应脚本或原始结果。
- `测试知识沉淀阶段细化方案.md` 属于参考资料，不作为默认输入。
- 已在 `批次摘要.md` 或系统测试报告中稳定表达的当前批次事实，只做链接和引用，不再当作知识条目重复展开。

# 知识可信度
| 等级 | 含义 | 使用方式 |
|------|------|----------|
| 已验证 | 有执行报告、原始结果或评审记录支撑 | 可直接作为下一轮输入 |
| 高可信 | 有文档和多个报告交叉支撑，但未实际执行 | 可作为设计依据，执行前复核 |
| 待确认 | 来源冲突、证据不足或环境未执行 | 下一轮必须优先确认 |
| 已过期风险 | 与当前实现不一致或依赖旧版本 | 只能作为历史参考 |

## 回归测试资产索引
字段必须包含：序号、资产类型、模块/场景、关联需求、关联用例、关联脚本、执行层级、优先级、最近执行结果、维护状态、可信度。

## 缺陷模式库
字段必须包含：模式编号、缺陷模式、典型缺陷、触发条件、影响范围、检测方法、预防建议、可信度。

## 自动化资产维护清单
字段必须包含：序号、专项、脚本路径、覆盖用例、当前状态、问题/价值、维护动作、优先级、阻塞原因、下一步。

## 环境与工具问题库
字段必须包含：序号、问题类型、表现、影响阶段、证据来源、解决方式、下轮准备动作、责任边界、可信度。

## 嵌入式端云联调知识库
字段必须包含：序号、协议/设备项、上报/查询/展示链路、样例来源、验证方式、已覆盖范围、未覆盖范围、待确认项、可信度。

## 流程决策模式库
字段必须包含：序号、专项、冒烟现象、关键证据、决策状态、为什么这样决策、后续动作、适用前提、不可复用边界、可信度。

# 强制规则
- 只有系统测试报告已生成后才允许执行本阶段。
- 不得把 `tests/` 全目录扫描作为默认动作；必须先从系统报告、覆盖矩阵或批次摘要定位需要读取的脚本。
- 不执行测试，不生成新的测试结论，不替代系统测试报告。
- 不得把待确认项沉淀为确定知识。
- 不得把未确认的接口文档契约沉淀为确定知识；真实接口可访问时，知识库应优先沉淀实测接口基线，并把文档差异标记为待确认或已过期风险。
- 不得把一次性环境现象写成通用产品规则，除非有证据支撑。
- 必须区分“项目特有结论”和“可复用流程规则”；只有后者可以作为跨项目配置沉淀。
- 必须说明流程规则的适用前提，避免把当前环境偶发现象写成通用决策模板。
- 不得明文保存密码、token、cookie、session、设备密钥、真实业务敏感数据。
- 不得修改历史测试报告、缺陷清单和执行结果。
- 不得删除旧知识；产品迭代导致变化时，应标记“已过期风险”并新增新条目。
- 嵌入式第一版只沉淀 protocol-cloud，不得写成完整嵌入式端侧知识库。
- 输出必须按顺序包含：当前阶段、输入文件、产出文件、正文/核心内容、执行结论、风险与待确认项、下一步建议。正文/核心内容必须位于执行结论、风险与待确认项、下一步建议之前；执行结论、风险与待确认项、下一步建议必须作为文档收尾部分。
