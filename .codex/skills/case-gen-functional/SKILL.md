description: 根据需求分析报告、测试方案和测试计划生成功能测试用例。仅生成功能测试用例，不生成接口、嵌入式、性能或安全用例，不执行测试。

# 输入
- `docs/AI执行最小规则.md`
- `docs/analysis/需求分析报告.md`
- docs/test-plan/测试方案.md
- docs/test-plan/测试计划.md
- `docs/reports/测试用例生成阶段细化方案.md`（仅在当前 SKILL 未覆盖细节时按需读取）
- docs/阶段执行检查清单.md

# 输出
- docs/cases/功能测试用例.md

# 覆盖维度
- 需求分析报告中的功能模块、页面与交互流程、业务实体、状态流转、异常场景、测试关注重点
- 主流程
- 分支流程
- 异常流程
- 边界值
- 权限控制
- 状态流转
- 数据校验
- 兼容性关注点

# 用例字段
- 序号
- 用例编号
- 模块
- 用例标题
- 前置条件
- 测试数据
- 步骤
- 预期结果
- 优先级
- 自动化结论
- 执行层级
- 来源依据
- 追踪标识

# 自动化与层级
| 场景 | 层级 |
|------|------|
| 登录、首页、核心菜单、核心页面可达 | smoke |
| 列表、筛选、详情、只读弹窗 | readonly-regression |
| 写操作入口、弹窗、必填校验，不提交 | semi-auto |
| 新增、编辑、删除、处理、同步、改密 | write-regression，需回滚策略 |
| 纯人工判断、视觉验收、复杂业务确认 | manual |

# 强制规则
- 测试方案或测试计划不存在时，不得生成正式用例
- 需求分析报告缺失或无法追溯时，不得生成正式用例
- 每条正式用例必须能追溯到需求分析报告中的模块、页面、流程、角色权限、状态、业务规则或实际观察行为
- 如果测试方案与需求分析报告不一致，不得自行选择口径；必须记录差异并标记待确认
- 需求分析报告没有依据、但测试方案认为需要覆盖的内容，必须标记“来源待确认”
- 不确定的前置条件、测试数据、预期结果必须写“待确认”
- 必须包含“序号”列，且位于“用例编号”前，从 1 连续递增
- 必须包含自动化结论和执行层级
- 必须输出生成统计：正式用例数、后续范围/阻塞数、优先级分布、自动化结论分布、执行层级分布
- 不得只写“正常”或“成功”作为预期结果
- 只输出功能测试用例，不输出接口、嵌入式、性能或安全用例
- 输出必须按顺序包含：当前阶段、输入文件、产出文件、正文/核心内容、执行结论、风险与待确认项、下一步建议。正文/核心内容必须位于执行结论、风险与待确认项、下一步建议之前；执行结论、风险与待确认项、下一步建议必须作为文档收尾部分
