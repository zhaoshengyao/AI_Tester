# 输入
- docs/AI执行最小规则.md
- docs/cases/安全测试用例-评审版.md
- docs/阶段执行检查清单.md
- docs/reports/性能测试报告.md
- docs/reports/参考资料索引.md
- docs/reports/自动化与专项执行阶段编排方案.md（仅在当前 SKILL 未覆盖细节或需追溯历史设计时按需读取）

# 输出
- tests/security/
- tests/security/reports/
- docs/reports/安全测试报告.md
- docs/defects/安全缺陷清单.md

# 工作流
1. 先读取 `docs/AI执行最小规则.md`，再读取安全测试用例
2. 检查性能测试是否已完成或明确未执行原因
3. 检查 ZAP/Docker 配置、执行入口和扫描授权
4. 确定扫描范围、URL、认证方式
5. 生成或更新 ZAP 扫描脚本/配置
6. 静态校验扫描范围和认证配置
7. 先执行安全基线/低风险检查，确认目标稳定性和认证上下文
8. 分析基线结果和目标稳定性，判断授权、误伤风险和服务承载风险
9. 输出下一步决策：continue/retest/collect-evidence/downgrade/stop/handoff
10. 仅在下一步决策为 continue 且授权明确时，调用 ZAP 被动/主动扫描
11. 汇总漏洞等级、证据和复现方式
12. 输出报告和漏洞清单

# AI 读取优化
- 默认输入顺序：`docs/AI执行最小规则.md` -> 评审版用例 -> 性能正式报告 -> 阶段门禁清单。
- `自动化与专项执行阶段编排方案.md` 只作为参考资料，不作为默认输入。

# 执行入口
- Windows: `pwsh -File scripts/run-security-tests.ps1`
- Bash: `bash scripts/run-security-tests.sh`

# 报告必须包含
- ZAP 安装目录：`C:\Program Files\ZAP\Zed Attack Proxy`。
- ZAP 启动方式或执行命令、执行时间、被测地址。
- 扫描目标、排除范围、认证上下文、扫描强度。
- 被动扫描、主动扫描、手工安全基线的执行范围。
- 漏洞等级、证据、复现方式、影响范围。
- 原始 ZAP HTML/JSON/XML 或基线扫描结果路径。
- 安全基线后分析和下一步决策，说明为什么继续主动扫描、降级为被动扫描、停止或移交。
- 未执行的扫描类型和原因。

# 强制规则
- 安全测试必须在性能测试之后执行
- 性能测试尚未完成且未明确未执行原因时，不得执行安全测试
- 未确认授权扫描范围、目标 URL、认证方式时，不得执行 ZAP 扫描
- 未确认 ZAP 启动方式、端口、认证上下文、排除范围、扫描强度时，不得执行 ZAP 扫描
- 若 API/UI 阶段存在连接级失败，安全测试必须标记“未执行”，不得继续扫描
- 安全基线后不得默认主动扫描；必须基于授权范围、目标稳定性、性能结果和误伤风险输出下一步决策。
- 性能 smoke 未达标或目标不稳定时，默认不得执行主动扫描；只能 stop/downgrade 或等待用户明确接受风险。
- ZAP 本地安装目录已知：`C:\Program Files\ZAP\Zed Attack Proxy`；执行前仍需确认启动脚本或可执行文件
- 生成 ZAP 脚本或配置不等于已执行安全测试；报告必须区分“已生成”“已执行”“未执行”
- 未实际执行 ZAP 时，报告必须写“未执行”并说明原因
- 原始 ZAP HTML/JSON/XML 或基线扫描结果必须保存到 `tests/security/reports/`，没有原始结果时必须说明原因
- 扫描结果不得等同于系统安全结论，必须说明覆盖范围
- 输出必须按顺序包含：当前阶段、输入文件、产出文件、正文/核心内容、执行结论、风险与待确认项、下一步建议。正文/核心内容必须位于执行结论、风险与待确认项、下一步建议之前；执行结论、风险与待确认项、下一步建议必须作为文档收尾部分
