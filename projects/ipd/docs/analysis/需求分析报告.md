## 4. 正文/核心内容

### 4.1 系统概述

IPD（Integrated Product Development，集成产品开发）管理系统是一套企业级研发项目管理平台，基于 RuoYi/ZwBoot 微服务框架开发。本次被测部署在 `192.168.2.97:6090`，用户身份为"赵经理"（项目经理角色）。

**核心定位**：以项目为主线，覆盖看板综合统计 → 项目立项/执行/结项全生命周期 → 项目过程中的风险预警 → 变更/预算/文档/审批管控 → 工作流引擎底层支撑。

**已识别菜单层级**（对应路由 `/dashboard`、`/idmp`、`/workflow`）：
```
统计分析看板
└── 项目综合看板         (路由: /dashboard/overview)

项目管理 (/idmp)
├── 项目列表             (路由: /idmp/project)
├── 审批中心             (路由: /idmp/approval)
└── 风险预警配置         (路由: /idmp/riskRule)

工作流 (/workflow)
├── 流程分类             (路由: /workflow/category)
├── 表单管理             (路由: /workflow/formManage)
├── SPEL 表达式          (路由: /workflow/spel)
└── …(其余由菜单返回,见菜单结构.json)
```

### 4.2 核心业务流程（基于页面 + 接口推断，未确认处标注）

#### 4.2.1 项目生命周期流程
```
草稿(draft)  → 立项评审 → 已立项(approved) → 概念(concept)
                                               ↓
                             结项(closed) ← 计划(plan) ← 执行(executing) ← 里程碑推进
```
- 字段 `status` 枚举值（从项目列表推断）：`draft / approved / ...`（待确认完整列表）
- 字段 `phase` 枚举值（从项目列表实测）：`concept / plan / closed / ...`
- 风险预警逻辑从 `riskRule` 表看：成本超支、里程碑逾期、任务逾期 3 大类 5 条规则，支持阈值配置 + 级别（高/中/低）

#### 4.2.2 风险预警流程
```
项目数据变化 (成本/里程碑/任务) → 匹配 riskRule.triggerCondition
                                    ↓
                          生成 risk 记录 (level=high/medium/low)
                                    ↓
                          看板 riskStats 统计 + 高风险项目标记
```
- 实测 `/idmp/riskRule/list` 返回 5 条规则：BUDGET_WARN(90%)、BUDGET_CRITICAL(110%)、MILESTONE_WARN(3d)、MILESTONE_CRITICAL(7d)、TASK_DELAY(5d)
- 实测 `/idmp/risk/list` 返回 3 条高风险（均为 open 状态，项目：回路监控箱设备），看板 `riskProjects=2`

#### 4.2.3 预算/成本管控流程
```
立项时输入 budget → 执行过程累计 spent
        ↓
   budget.status (draft 等)
        ↓
   实际支出超阈值 → 触发 BUDGET_WARN / BUDGET_CRITICAL
```
- 实测 `budget` 字段：`{id, projectId, totalBudget, spent, status}`

#### 4.2.4 工作流审批流程
```
流程分类 (workflow/category) → 流程定义 (definition) → 关联表单
      ↓
   发起审批实例 → 待办/已办 → 审批通过/驳回
      (注: approval/{list|myPending|myDone|myStarted} 均为 /approval/{id} 形式，
      说明 approval 模块存在详情接口，但 REST 路径为 /idmp/approval/{approvalId}
      —— 列表接口可能是 POST /idmp/approval/_search 或另一种分页形式，待确认)
```

### 4.4 认证协议与实测接口基线（文档与实际差异）

> 由于没有接口文档，本节作为"实测基线文档"供后续 API 用例和自动化脚本引用。后续阶段若拿到正式文档，应通过"文档与实际差异"章节对比。

#### 4.4.1 登录接口差异（与 CRM 默认约定对比）

| 项 | 框架 / CRM 默认 | IPD 实测 | 差异说明 |
|----|-----------------|----------|----------|
| `login_path` | `/prod-api/system/login` | `/prod-api/auth/login` | **不同**：/system/login 在 IPD 返回 404 |
| `client_id` 字段名 | `client_id`（下划线） | `clientId`（驼峰） | **不同**：下划线形式服务端会报"认证客户端id不能为空" |
| `grant_type` 字段名 | `grant_type`（下划线） | `grantType`（驼峰） | **不同**：下划线形式服务端会报"认证权限类型不能为空" |
| `password_encryption` | AES-256-GCM（项目初始占位） | AES-256-ECB | **不同**：GCM 不匹配；IPD 使用 32 字节 client_id 字符串直接作为 ECB key |
| 加密 key 来源 | N/A（占位） | client_id 完整 32 字节 UTF-8 字符串 | IPD 特定约定 |
| `tenantId` 额外字段 | 不传 | 必须传 `tenantId: "000000"` | IPD 必须（字段名 tenantId 驼峰） |
| token 返回位置 | `data.access_token` | `data.access_token` | ✅ 一致 |
| token_type | Bearer | Bearer | ✅ 一致 |
| token 携带方式 | Header `Authorization: Bearer {token}` + `clientid: {clientId}` | ✅ 同样 | ✅ 一致 |

> **待确认项 #1**: JWT 中 `clientid` 全小写（与 body 的 `clientId` 大小写不同）属于 IPD 后端序列化风格，已用 JWT.io 解码确认 payload 内容正确，不影响认证流程。

### 4.7 数据一致性验证线索（来自接口返回的重复口径）

- **A1 统计一致性**：看板 stats.total = 5，项目列表 `project/list` 返回 5 条 → ✅ 当前一致。
- **A2 项目类型统计**：typeDistribution hardware×3 + software×2 = 5 → ✅ 与项目列表 3 硬+2 软 一致。
- **A3 风险分布**：riskStats high=3 medium=1 low=0 → 当前 risk/list 返回 3 条 high 且都属于同一项目；medium 的 1 条来自其他项目但列表没有，可能是当前查询默认 projectId 过滤 → **用例阶段需验证查询参数是否过滤全局/项目级**（这是一个潜在不一致风险点）。
- **A4 项目进度 vs risk 项目数**：riskProjects=2，projectProgress 中 riskLevel=high 的项目数=1（回路监控箱设备）；其余 4 条 riskLevel 分别有高/中/低，需要确认 riskProjects 统计口径（是否"至少有 1 条 open 风险"）。
- **A5 文档数量**：document/list 3 条都有 projectId，需要和对应项目的文档数字段对比（项目详情没有 documentCount 字段），一致性只能通过列表内计数验证。
