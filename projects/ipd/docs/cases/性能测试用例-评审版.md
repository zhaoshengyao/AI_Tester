## Warm-up 预热阶段（OM-06 新增，不计入正式统计）

- **warm-up 参数**：1 user，1/s spawn，10s 持续
- **warm-up 接口**：同上 5 只读高频接口
- **目的**：消除首次 JIT / 数据库连接池初始化导致的 P95 突增（避免误判为 retest）
- **不计入**：warm-up 阶段的 RPS / P95 / 错误率 **不进入任何专项统计和门禁判定**

## Locust 事件钩子（test_stop / 错误 / 心跳，强制实现 OM-09 + 数据打点）

**必须实现以下钩子（否则按"脚本未实现实时门禁"记为 semi-auto 降级执行）**：

```python
# ==================== OM-09 实时错误率监测钩子 ====================
consecutive_high_err_seconds = 0    # 连续高错误秒数计数
last_rps = None

@events.test_stop.add_listener
def on_stop(**kwargs):
    """每 10s 统计打点 CSV（users/rps/p50/p95/p99/fail_ratio），用于折线图"""
    pass  # 实际实现：10s 定时器写入 perf_metrics_YYYYMMDD-HHMMSS.csv

@events.request.add_listener
def on_request(request_type, name, response_time, response_length, exception, context, **kwargs):
    global consecutive_high_err_seconds, last_rps
    # 1) 异常/错误立即记 1
    if exception:
        pass
    # 2) 心跳 1s 级别：若最近 10s fail_ratio > 5% → consecutive+1；>3 倍连续 → quit
    if consecutive_high_err_seconds >= 10:   # 约 10s 高错误率
        print(f"[PERF-STOP] 错误率连续 10s > 5%，按 OM-09 立即停止压测。")
        try:
            env.runner.quit()   # type: ignore  # pylint: disable
        except Exception:
            pass

    # （简化实现：最后 20% 区间对比，实际脚本里细化）
```

## 决策状态映射（符合 AGENTS.md 自适应执行规则 6 态）

| PERF-001 结果 | PERF-002 结果 | 决策状态 | 后续动作 |
|--------------|--------------|----------|----------|
| ✅ 全部达标 | ✅ 全部达标 | **continue** | 执行 PERF-003 full 50 用户 300s |
| P95 1500–3000ms 或错误率 1–2% | ✅ 通过但勉强 | **downgrade** | 跳过 PERF-003，执行 PERF-004 降级 15 用户 180s |
| 错误率 >5% 或 P95 >3000ms | ✅ 通过 | **retest** 或 **collect-evidence** | 收集服务端日志/CPU/Mem/DB 连接池证据，缩小范围（10 用户 60s）后复测，或直接 handoff 给研发定位服务端稳定性问题 |
| ✅ 达标 | 恢复 P95 仍 > 500ms（第一次）→ retest 后仍不通过 | **stop** | 停止 full/安全加压专项；系统报告中登记"加压后服务恢复不足，不得继续性能/安全 full 专项" |
