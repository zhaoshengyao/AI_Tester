# IPD 管理系统 性能测试用例（初稿）

> **说明**: 共 4 条（测试计划预估 4）。编号前缀 `PERF-`。Locust 配置见 system.yaml `performance.smoke` / `full`。**核心门禁规则**：
> - smoke 通过门槛：错误率 < 1%、P95 < 1000ms、P99 < 2000ms、停止压测后 30s 恢复 smoke 通过
> - full 通过门槛：错误率 < 3%、P95 < 3000ms、P99 < 5000ms、吞吐稳定（±30% 内）
> - **如未安装 Locust，所有用例标注"未执行：Locust 未安装"（AGENTS.md 自动化规则）。**

| 序号 | 用例编号 | 类型 | 用户数 | Spawn | 持续 | 接口（只读高频） | 优先级 | 门禁决策要点 | 通过/失败判定 |
|------|----------|------|--------|-------|------|-----------------|--------|--------------|--------------|
| 1 | PERF-001 | smoke | 5 | 1/s | 60s | 1. `GET /idmp/dashboard/overview`<br>2. `GET /idmp/project/page?pageNum=1&pageSize=10`<br>3. `GET /idmp/riskRule/list`<br>4. `GET /workflow/category/list`<br>5. `GET /workflow/definition/list?pageNum=1&pageSize=10` | P2 但门禁级 | **门禁：不通过 → 不得进入 full 压测，也不得继续 UI/安全等会放大风险的专项（AGENTS.md）** | 错误率 < 1%；P95 < 1000ms；P99 < 2000ms；峰值 QPS 稳定（最后 20% 区间 QPS 波动 ≤ ±30%） |
| 2 | PERF-002 | 恢复 smoke | 1 | 1/s | 10s | 同上 5 接口（在 PERF-001 结束 30s 后立即执行） | P2（恢复检查） | 恢复能力是门禁继续的前提：不通过 → 说明加压后服务未恢复，禁止后续 full + 其他专项 | 5 个接口 100% code=200；P95 < 200ms；无 5xx |
| 3 | PERF-003 | full（默认） | 50 | 5/s | 300s | 同上 5 接口；请求比例 = overview 30% / project 30% / 其他各 ~13% | P2 | 仅在 PERF-001 + PERF-002 同时通过才执行；否则 downgrade PERF-004 | 错误率 < 3%；P95 < 3000ms；P99 < 5000ms；没有断崖 QPS 掉 50% 以上；无连续 5xx（>3 个即不稳定） |
| 4 | PERF-004 | full（降级） | 15 | 2/s | 180s | 同上 5 接口（但加压强度为默认的 30%） | P2 | 触发条件：PERF-001 P95 在 1500–3000ms 之间或错误率 1–2%，但服务端恢复 smoke 通过 → 降级到 15 用户运行小 full | 同一门槛比例缩放（错误率 < 2%；P95 < 2000ms）；不通过 → stop 并登记"服务端承压能力低于预期 50% 目标" |

### 关键参数权重比例（Locust tasks.py 中使用）

```
overview    3/10 = 30%   # 最复杂聚合查询（必压）
project    3/10 = 30%   # 主列表 + 分页
riskRule   1.3/10 = 13%
wf-category 1.3/10 = 13%
wf-def     1.4/10 = 14%
合计 = 10
```

### 失败自动标记机制（写 Locust events 钩子）

- **错误率 ≥ 3%** → 标记性能专项为 `retest`（环境波动）或 `collect-evidence`（日志）
- **P95 ≥ 4000ms 连续 30s** → 标记 `downgrade`/`stop`
- **大量 Read timed out** 或连接 ResetError → 立即 `stop`（不放大风险，AGENTS.md 性能门禁规则）
- **每 10s 打点 CSV**：users、rps、p50、p95、p99、fail_ratio → 用于生成性能报告折线图
