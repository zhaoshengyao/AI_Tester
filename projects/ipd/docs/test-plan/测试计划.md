# IPD 管理系统 测试计划

## 1. 当前阶段
- **阶段**: 测试设计阶段（测试计划）
- **输入**: 测试方案 v1.0 + 需求分析报告 v1.0（实测基线）
- **执行原则**: 所有日期均为"相对第 0 天（即测试方案通过当天）+N 工作日"，绝对日期填入批次目录。

## 2. 输入文件
- `projects/ipd/docs/test-plan/测试方案.md` — 范围、策略、分层、各专项门禁决策
- `projects/ipd/docs/analysis/需求分析报告.md` — 56 项功能单元 + 18 条接口 + 11 条风险
- `projects/ipd/system.yaml` — 系统与工具配置
- `projects/ipd/.env` — 账号与 URL

## 4. 测试目标

| 目标类型 | 目标描述 | 验收标准（准出） |
|----------|----------|------------------|
| **功能覆盖率** | 覆盖 56 项功能单元中所有 P0 + P1 | P0 功能覆盖率 100%；P1 ≥ 90% |
| **接口基线覆盖** | 18 条 ✅ GET API 每条 ≥ smoke（200 断言），并按分层再覆盖分页/过滤/详情 | smoke 18/18 通过；readonly 分页/过滤/详情 ≥ 80% |
| **核心看板一致性** | A1/A2/A3/A4/A5/A6 6 条一致性 | P0 的 A1/A2/A4/A6 100% 通过；A3/A5 若发现口径差异则进入 collect-evidence，不直接判失败 |
| **数据权限边界** | dept/role/menu/build 三项 403 + user/list 越权 R4 合规判定 | 403 三项 3/3 通过；R4 必须给出合规 yes/no 结论 |
| **端到端闭环** | 至少 1 条沙盒项目的完整 write-regression：创建→阶段推进→预算→风险→结项（成功或失败） | 流程完整走通（允许失败但必须有明确的失败原因与缺陷登记） |
| **自动化率** | smoke 100% 自动化；readonly P0 100% 自动化；semi-auto 写操作弹窗 ≥ 80% 自动化 | 覆盖矩阵中对应比例的"已实现脚本/已执行"两项均达成 |
| **缺陷归档** | 所有失败项（API/UI/性能/安全）全部进入缺陷清单，关闭方式明确 | 缺陷清单条目数 == 各专项失败条数之和；每条有关闭方式字段 |
| **门禁决策合规** | 每个专项门禁决策状态 != continue 时必须写决策依据；stop 后不执行下游专项 | 专项报告 6/6 有"下一步决策"小节；stop 后执行记录验证 |

## 9. 风险登记（测试侧执行风险）

| 编号 | 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|------|----------|
| ER1 | 登录接口认证协议变化（例如突然改为加密 key 长度变化） | 低 | 阻断所有自动化 | 脚本内置"登录失败 → 自动重新探测登录参数"逻辑；并在脚本失败时输出候选组合日志 |
| ER2 | 沙盒项目写操作导致脏数据未清理 | 中 | 影响测试环境 | 清理脚本 + 批次摘要中记录所有沙盒 projectId 清单；下一轮测试启动前先扫残留 |
| ER3 | 测试账号赵经理被锁定/密码被改 | 中 | 全程暂停 | `scripts/check-stage.ps1` 门禁阶段 0 先预登录 1 次；失败立即 handoff + 列出受影响的后续用例范围 |
| ER4 | 工作流真实提交后无人审批 → 流程挂起 | 中 | 端到端流程中断 | 写操作 semi-auto 只做到"点提交看提示"；真实提交必须使用自动化专用审批流（无权限则 downgrade） |
| ER5 | 性能 smoke 后被测服务无法恢复 → 后续 UI/安全专项异常 | 中 | 数据失真 | 性能后必跑"恢复 smoke"：停止压测 30s 后重查 dashboard 接口，3/5 通过才允许后续专项继续；如果不通过 → 专项报告中写"性能后未恢复，后续专项降级/未执行" |
| ER6 | R4 越权结论不清晰（产品/研发无法及时答复合规 yes/no） | 中 | 安全专项阻塞 | 系统报告中标记"R4 待确认：项目经理是否有权限查看全员手机号邮箱？" 并登记为"待确认项"，不关闭缺陷；知识沉淀中同步登记 |
| ER7 | 所有接口命名规范不统一（`list` vs `page` vs 数组 return vs {total,rows}） | 中高 | API 自动化脚本维护成本高 | 知识沉淀中登记"IPD 接口返回结构对照表"，每条接口单独写结构类型；脚本 fixture 提供 `assert_response_structure()` 自动适配 2 种结构 |
