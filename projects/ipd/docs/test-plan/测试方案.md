## 5. 测试策略

### 5.1 测试类型与工具

| 测试类型 | 覆盖范围 | 工具 / 方式 | 执行分层（按 AGENTS.md 自动化分层规范） |
|----------|----------|-------------|----------------------------------------|
| 功能测试 | 62 项功能单元的正常/异常/边界 | 评审版用例 + Playwright 交互 | smoke → readonly-regression → semi-auto → write-regression（沙盒） |
| 数据一致性测试 | A1–A5 5 条线索 + 看板统计与列表核对 | API 查询比对（TR-001/TR-002/TR-005 严格执行） | readonly-regression，与 API smoke 同步执行 |
| API 自动化测试 | 18 条 ✅ 接口 + 参数组合 + 分页 + 过滤 | pytest + requests（项目现有框架） | smoke=18 条 200；readonly=详情/分页/过滤/字典；semi-auto 不提交 |
| UI 自动化测试 | 所有 6 菜单页面 + 列表筛选弹窗交互 | Playwright（与 system.yaml 中 global-setup 配合） | smoke=登录+6 菜单可达；readonly=列表/筛选/详情；semi-auto=弹窗打开+必填校验 |

### 5.6 写操作安全（沙盒 + 回滚）

> 因无需求文档，必须避免污染现有 5 条项目数据。以下为硬性规定：

1. **所有写操作必须先在 semi-auto 层跑通（弹窗+校验），禁止直接提交。**
2. **真实写操作（write-regression）只针对专用沙盒项目**：
   - `projectCode = TEST-AUTO-YYYYMMDD-HHMM`（时间戳唯一）
   - `projectName = 测试自动化沙盒项目-勿动`
   - `client = 自动化`
   - `type = software`（无实际业务影响）
   - `managerId = 当前赵经理`（保证有权限删除）
3. **回滚策略**：
   - 软删除：若存在 `/idmp/project/{id}` DELETE 接口 → 执行删除
   - 硬标记：若没有删除接口 → 项目 name 追加 `[已作废-可清理]`，status 改为 closed
   - 测试执行完 write-regression 后 24h 内运行清理脚本（在报告中记录清理脚本路径，若未实现则写"清理脚本待实现，当前为人工标记"）
4. **工作流审批写操作**：如果真实提交需要走审批链，**不得用真实业务流程（IDMP审批）做自动化**，改为 semi-auto 只点提交看提示，然后退出。专用流程需要提前创建"自动化专用审批流"（如果无权限则写"未执行：审批链无自动化专用流"）。

## 6. 各专项测试设计要点

### 6.1 API 自动化（pytest + requests）

**设计要点**：
- **认证 fixture**：提前调用 `/prod-api/auth/login`（AES-256-ECB）拿 token；每个 session 重取一次；另外准备 3 个 fixture：过期 token、空 token、错误 clientId → 用于权限专项
- **公共结构断言**：所有接口必须有 `{code, msg, data}` 3 字段（除 `workflow/definition/list` 外多一个顶层 `total` 和 `rows`）→ 报告两种结构都合法
- **分页参数组合矩阵**：
  - `(pageNum, pageSize)` ∈ {(1,1), (1,3), (1,10), (1,100), (2,3), (99,100)}
  - 空页 / 末页 / 超大页 / 非法页（pageNum=0、负数、非数字）
- **过滤参数矩阵**：
  - project：`type ∈ {hardware, software, 非法值}`
  - risk：`level ∈ {high, medium, low}`、`projectId ∈ {已知项目id, 不存在id, 空}`
  - workflow：`categoryId ∈ {已存在分类, 不存在, 空}` 同时尝试 `category` / `category_id` 别名（解决 R10 参数名未确认）
- **写操作 semi-auto（POST/PUT 不实际提交最终状态）**：
  - 新建项目用必填缺失 → 期望必填校验错误码（记录真实错误码，不按文档断言）
  - 字段长度超长 → 记录真实错误码
  - 不执行 PUT 到真实存在项目 id=2086985… 的数据修改

**API 门禁决策（冒烟后）**：
- **continue**：`smoke` 18 条 100% code=200 且 P0 的一致性 A1/A2/A6 通过
- **retest**：失败 < 3 条且疑似偶发（连接超时 504 等）→ 原条件重试
- **collect-evidence**：一致性 A1–A4 失败 → 打印两边原始 JSON + 按 projectId 对账明细，不直接判失败
- **downgrade**：登录成功但审批/里程碑接口仍未确认 → 降级为 readonly（仅已✅ 18 条），API full 关闭 R1–R3 相关写操作
- **stop**：登录失败 / 服务端 5xx 连接级 / base_url 不通 → 停止 UI、性能、安全专项（AGENTS.md 强制规则）
- **handoff**：返回 500 且 msg 含"空指针"/"SQL 异常" → 输出请求体、响应体、复现命令给研发，不再继续执行对应模块的写操作

### 6.2 UI 自动化（Playwright）

**设计要点**：
- **登录前置**：复用 `tests/ui/global-setup.ts`（system.yaml 指定），但需要适配 IPD 的 AES-256-ECB 加密和驼峰字段 — 建议先实现 `tests/ui/specs/ipd/login.setup.ts`
- **截图点位**：每个 smoke 页面 1 张，readonly 关键筛选结果 1 张，semi-auto 弹窗必填报错 1 张
- **主要交互路径**：
  - 看板：5 个卡片实际渲染、类型分布饼图 canvas 有数据、projectProgress 5 条进度条渲染
  - 项目列表：点击 type hardware/software tab（若 UI 有）、打开"回路监控箱设备"详情、返回列表
  - 风险预警配置：单条规则编辑按钮 → 弹窗（不提交）→ 关闭
  - 审批中心：点击 4 个 Tab（我的待办/已办/我发起/抄送）—— 即使 API 未确认，UI 页面展示要正常
  - 工作流分类：展开 3 级嵌套、点击分类后筛选流程定义列表
- **断言规则**：优先断言 `页面标题`、`列表空态或非空态`、`筛选后总数变化`；不做像素级对比
- **意外处理**：弹窗"权限不足"是预期（dept/role/build 三处），不要误判为失败

**UI 门禁决策（冒烟后）**：
- **continue**：登录 + 全部 6 子菜单可打开 + 关键列表非空（项目/风险/预算/文档/分类/流程定义）
- **retest**：单页面 timeout 或网络抖动 → 重跑对应单 spec
- **collect-evidence**：列表为空但 API 返回非空 → 抓 console 错误 + HAR + 截图，排查前端过滤是否 bug
- **downgrade**：4 个写操作弹窗打不开 → 降级为 UI readonly（放弃 semi-auto 部分），后续系统报告中写"UI 写操作未执行：原因 X"
- **stop**：登录失败 / 看板 500 / 所有菜单 404

### 6.3 性能测试（Locust）

**设计要点**（引用 system.yaml 已配置默认值）：
- 前置条件：Locust 已安装（`python -c "import locust"` 通过），否则报告写"未执行：Locust 未安装"
- **smoke 压测参数**：users=5，spawn_rate=1，duration=60s
- **压测端点集（仅只读高频）**：
  1. `GET /idmp/dashboard/overview`（最复杂聚合查询）
  2. `GET /idmp/project/page?pageNum=1&pageSize=10`
  3. `GET /idmp/riskRule/list`
  4. `GET /workflow/category/list`
  5. `GET /workflow/definition/list?pageNum=1&pageSize=10`
- **full 压测参数**：users=50，spawn_rate=5，duration=300s；仅在 smoke 满足门禁后执行
- **指标阈值（门禁）**：
  - 错误率 < 1%（smoke）、< 3%（full）
  - P95 < 1000ms（smoke）、< 3000ms（full）
  - P99 < 2000ms（smoke）、< 5000ms（full）
  - 吞吐稳定（最后 20% 时间的 QPS 波动 < ±30%，没有断崖式下降）

**性能门禁决策（冒烟后）**：
- **continue**：以上 4 项全部满足，且服务端 smoke 恢复后立即健康（停止后 30s 重查 dashboard 正常）
- **retest**：单端点 P95 略超（1000–1500ms）或错误率 1–2%，可能是网络抖动 → 再跑 1 次 smoke（duration=120s）
- **collect-evidence**：错误率 > 3%，或出现 Read timed out → 拉取被测服务 GC/CPU/连接池日志（如果有权限），同时停止加压
- **downgrade**：P95 在 1500–3000ms → 降级为 smoke 执行 + 小 full（users=15）；不跑 users=50
- **stop**：错误率 > 5% 或大量 504 / 服务级 500 → 停止压测，后续专项都不在错误态下继续（AGENTS.md 规则）
- **handoff**：服务端"内存溢出/Too many open files/DB down" → 输出证据、停止所有专项

### 6.4 安全测试（自定义扫描器 + 手工断言）

**设计要点**：
- 前置条件：`tests/security` 下存在扫描器入口；否则写"未执行：安全扫描器入口未配置"
- **冒烟基线（最低执行集合）**：
  1. **未授权访问**：不带 Authorization 与 clientid header 请求 18 条 API → 必须返回 401/403，绝不允许返回 200（这是硬缺陷）
  2. **R4 水平越权核查**：项目经理访问 `/system/user/list` 返回 16 人（含 admin 手机号/邮箱）——**手动判断合规性**，需要业务方确认："项目经理是否允许查看全公司用户手机号邮箱？"  → 如果业务方回答否，这是中高危缺陷
  3. **JWT 校验**：
     - token 末尾字符篡改 → 应返回 401
     - token 过期 → 应返回 401
     - 换另一个 clientId（随便填 `clientid: fakefakefakefakefakefakefakefak`）+ 正确 token → 应返回 401（多租户隔离）
  4. **SQL 注入冒烟**：对 `project/page?projectName=xxx' OR '1'='1` 等常见 payload（3–5 条），断言不出现 500 SQL 错误码，不返回超量数据
  5. **XSS 冒烟**：风险 `description=<img src=x onerror=alert(1)>`（semi-auto 不提交，只是打开 POST 请求看返回码——如果返回 400 有过滤则 OK；如果返回 200 写入成功则后续需查前端是否 escape）
- **深度扫描（ZAP 可选）**：若本机装了 ZAP，加跑 1 轮 passive 扫描，只输出"疑似项"并标注"需人工复核，不作为直接缺陷"

**安全门禁决策（冒烟后）**：
- **continue**：未授权 18/18 全 401/403；JWT 篡改 3/3 全 401；SQL 注入 0 条堆栈泄漏
- **retest**：1 条疑似因本地缓存（之前登录过）→ 清 cookie 重测
- **collect-evidence**：R4 越权需要业务合规判定 → 暂停安全深度，收集"当前 16 条 user/list 返回的字段清单"和"RACI 权限矩阵"，标注"待合规确认"
- **downgrade**：ZAP 未装 → 只跑基线冒烟（当前 5 项），深度不跑，报告中写"安全专项降级：仅冒烟通过"
- **stop**：未授权访问能拿到看板真实数据（200 + 业务 code=200）→ **高危！立即停止所有专项，禁止进一步加压/写操作**
- **handoff**：水平越权 R4 被确认不合规 → 直接登缺陷，转交产品/研发评估影响范围与修复
