## 二、API 测试对比分析

### 2.1 完全一致的结果
API 冒烟和全量测试在服务器和本地表现完全一致：
- **冒烟**: 14 passed / 0 failed
- **全量**: 4 failed / 120 passed / 23 skipped

### 2.2 相同的 4 个失败用例
| # | 用例名称 | 错误信息 | 根因分析 |
|---|----------|----------|----------|
| 1 | `test_wf08_verify_workflow_data_consistency` | 商机应关联正确的客户 ID 不匹配 | 测试数据隔离或缓存问题 |
| 2 | `test_customer_statistics_consistency` | 接口返回总数=1261, 计算总数=1000 | 硬编码预期值 vs 动态数据 |
| 3 | `test_business_statistics_consistency` | 接口返回总数=1419, 计算总数=1000 | 硬编码预期值 vs 动态数据 |
| 4 | `test_sales_funnel_consistency` | 各阶段总和=1000, 总商机数=1419 | 同上，统计口径问题 |

### 2.3 根因结论
1. **数据一致性测试缺陷**: 用例中硬编码了预期的统计数值(1000)，但实际系统已有 1261 个客户和 1419 个商机。**这是测试脚本设计问题，不是系统缺陷**。
2. **工作流数据不一致**: `test_wf08` 中客户 ID 不匹配，可能是前序用例创建的数据在缓存中被污染，或 API 返回了错误的关联关系。

**建议**: 修复测试脚本，使用动态获取的实际数据作为断言基准，而非硬编码预期值。

## 三、安全扫描对比分析

### 3.1 结果差异

| 指标 | 服务器 | 本地 | 差异 |
|------|--------|------|------|
| 总检查数 | 142 | 142 | 相同 |
| 通过数 | 138 | 135 | 本地少 3 |
| 失败数 | 4 | 7 | 本地多 3 |
| 漏洞数 | 3 | 6 | 本地多 3 |

### 3.2 漏洞差异

**服务器发现 (3 个)**:
1. `/.git/HEAD` - 敏感信息泄露
2. `/swagger.json` - 敏感信息泄露
3. `/openapi.json` - 敏感信息泄露

**本地发现 (6 个)**:
1. `/.git/HEAD` - 敏感信息泄露
2. `/config.ini` - 敏感信息泄露
3. `/.env` - 敏感信息泄露
4. `/.env.example` - 敏感信息泄露
5. `/swagger.json` - 敏感信息泄露
6. `/api-docs` - 敏感信息泄露

### 3.3 差异原因分析
本地扫描发现了更多漏洞（`config.ini`、`.env`、`.env.example`、`/api-docs`），而服务器未发现。可能原因：
1. **网络视角不同**: 本地与服务器处于不同网段，系统的访问控制策略可能因来源 IP 而异
2. **缓存状态不同**: 服务器可能有 CDN 或反向代理缓存，部分文件在服务器端被拦截
3. **扫描时序差异**: 两次扫描的时间点不同，系统配置可能有变化

**建议**: 统一从同一网络位置执行安全扫描，确保结果可复现。
